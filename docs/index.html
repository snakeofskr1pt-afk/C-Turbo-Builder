C++ builds:
cache what didn't change.

turbo hashes every translation unit — source, all transitively included headers, compiler flags and the compiler identity — reuses cached object files, and glues sources into parallel Unity Build chunks. One static binary. Zero dependencies. Works offline.

Download for Windows .zip Download for Linux .tar.gz Just turbo.exe direct executable

No Rust needed. You still need a C++ compiler for your own projects: g++, clang++ or cl.exe.

Quick start

turbo build --root C:\work\mygame --jobs 16 --chunk-size 10 -- g++ -Iinclude -O2
turbo C:\work\mygame            # same: drop a folder onto turbo.exe
turbo cache stats

What it does

Content-addressed cache

SHA-256 over source + every included header + flags + compiler. Unchanged units are never compiled twice. Cache hits cost tens of milliseconds, not seconds.

Parallel Unity Build

Sources are glued into chunks so shared headers are parsed once per chunk, then compiled in parallel and linked once.

Drop-in launcher

Use it as CMAKE_CXX_COMPILER_LAUNCHER or a CXX wrapper. Linking, preprocessing and dependency generation are forwarded untouched.

Zero dependencies

No crates. Hand-written SHA-256, JSON reader, include parser and thread pool — builds offline with nothing but rustc.

turbo.json

Compiler, flags, includes, defines, excludes, chunk size, jobs, output and linker in one file. Command line always overrides it.

Honest failure modes

Failed compilations are never cached; an unwritable cache only warns and disables caching instead of failing the build.

Honest numbers

Cold-build speed-up depends on the project: fewer compiler invocations, but a big translation unit costs more than a small one. A no-op rebuild is just hashing + linking (<100 ms in the demo project). Measured tables and the benchmark script live in the README. v0.1.0 caveats: not yet validated against a real MSVC/GCC toolchain by the author, system headers are not hashed, no PCH support yet.
